STEP 16 — GAME-LIKE FULL SCENE CACHE

ЦЕЛЬ:
После первого прогрева переключение между магазинами вообще не должно
запускать видимую загрузку товаров или картинок.

КАК ТЕПЕРЬ РАБОТАЕТ:

1. При первом входе приложение получает список активных магазинов.
2. В фоне ПАРАЛЛЕЛЬНО загружаются каталоги ВСЕХ активных магазинов.
3. Для каждого каталога заранее прогреваются и decode() ВСЕ изображения товаров.
4. Готовые сцены лежат:
   - в RAM (мгновенный switch);
   - в sessionStorage (повторный заход в этой вкладке/сессии тоже мгновенный).
5. Во время клика SWA6Y5TAN ↔ ZULF:
   - НЕТ getShopProducts в обычном сценарии;
   - НЕТ skeleton;
   - НЕТ ожидания изображения;
   - React просто подставляет готовый массив из памяти;
   - Motion делает короткий визуальный переход.
6. Если пользователь меняет сортировку, приложение заранее строит сцены
   всех магазинов уже для этой сортировки.
7. Фильтры/search по-прежнему могут делать API-запросы — но при смене магазина
   они сбрасываются, поэтому сам переход магазина остаётся кэшированным.
8. Если preload конкретного магазина по сети упал, сохранён fallback:
   при клике он догрузится. Это аварийный случай, а не обычный путь.

ВАЖНО:
Это сознательно более тяжёлый старт ради абсолютно бесшовной навигации потом.
Для 2–нескольких магазинов это оптимально.
Если магазинов станут десятки/сотни, позже заменим на умный LRU/predictive preload.
